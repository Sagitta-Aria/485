## 用户需求与背景

用户反馈：“第二次测量成功了，但是没有给到具体接线的测量电阻值，这个应该补充上”。

现有系统由上位机通过 WiFi 连接两个 Master，每个 Master 管理本侧独立 RS485 总线上的从机。每侧支持 1 至 10 台从机，界面默认 7 台，实际数量由用户填写并在扫描前验证；每台从机提供 24 组相邻 X 双触点。

正常扫描左端为 master1，右端为 master2，使用 master1 的 XD31H。master1 的 S1 固定闭合 X0-Y0、X1-Y1、X2-Y2、X3-Y3；master2 本地矩阵保持断开。详细接线与身份配置以 `docs/topology_scan.md` 和当前实际固件配置为准，不要因本次交接覆盖用户烧录时调整的配置。

历史背景：两侧可使用相同的本地 RS485 从机编号，WiFi 调试 ID 已按所属主机区分，例如 `m1-s1` 和 `m2-s1`。从机 WiFi 调试代码保留，拓扑扫描不依赖从机直连上位机。这些是已有功能，不属于本次修改。

## 问题与处理

原控制器保存了原始单点读数，但行结果没有携带阻值，界面也没有电阻列。另外，正常唯一编码的接线原来不做单点测量，不能直接把分组测量读数当成这条接线的电阻。

本次行为：

1. 原有恒重编码初筛保持不变。
2. 短路候选、不确定或不一致的行仍执行异常逐点补测，其读数直接复用。
3. 编码识别出的唯一接线，若尚无单点读数，追加一次现有 `TOPO_POINT` 测量。
4. 单点测量同时用于电阻显示和接线复核。超时、阈值区间或与编码矛盾的结果不能继续显示为正常连接。
5. 即使复核失败导致最终确认目标为空，也保留编码曾识别的目标及其复核读数，方便追查。
6. 取消或失败时保留已完成读数，尚未测量的阻值明确标记 `NOT_MEASURED`，不补成零。

测量次数示例：

| 配置与接线 | 无异常时总次数 |
|---|---:|
| 每侧 1 台，只连接一根线 | 168 + 1 = 169 |
| 每侧 1 台，24 路一一连接 | 168 + 24 = 192 |
| 每侧 7 台，168 路一一连接 | 1680 + 168 = 1848 |
| 每侧 10 台，240 路一一连接 | 2400 + 240 = 2640 |

异常会增加测量次数，以上不是复杂故障下的次数或耗时保证。没有跨端导通的行不会仅为显示电阻而额外扫描全部右端口。

## 报告与读数语义

- JSON 新报告使用 `schema: 2`，保留原字段，增加顶层 `resistance_basis: "single_point_uncalibrated"`。
- 行结果新增 `connection_resistances`，各项包含 `target`、`target_global`、`resistance_ohm`、`bit`、`reason`、`raw`、`raw_value`、`range_code`。
- 此列表包括已确认目标，也可能包括编码曾识别但复核失败的目标。不能仅凭目标出现在列表中就判断导通，应结合行 `status`、`targets` 及测量 `bit`。
- CSV 保留原接线矩阵和原始数据列，末尾为每个右端口追加 `resistance_ohm:<端口>` 和 `resistance_status:<端口>`。
- 数值保留三位小数。真正的零值为 `0.000`；无数值时 JSON 使用 `null`，CSV 留空，原因单独记录。
- 阻值是未校准的单点端到端 XD31H 读数，不是分组并联读数，也没有扣除夹具或开关通路影响。不能宣称等于芯线本体电阻；短路网络可能得到等效电阻。
- 旧报告不会自动改写，未增加旧报告导入界面。

## 已有实测证据

用户第二次成功扫描的历史报告：

`D:\esp32\cable_tester_rs485\reports\topology\topology_20260907_163411_9fd30d6c.json`

报告无终止错误，包含 168 个编码样本和 24 个异常补测样本。唯一确认连接为左侧 `slave1-G1` 到右侧 `slave1-G1`，原始单点响应是：

```text
OK MEASURE resistance=25.380 raw=2538 range=1
```

也就是 **25.380 ohm**。这不是修改后重新测量的结果，而是旧报告已有读数。该源端的分组读数约为 77 至 81 ohm，说明不能用分组值替代单点值。历史报告保持原样。
