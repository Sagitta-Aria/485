# Goal：RS485 主控制台单点调试与全矩阵复位

目标工程为 `D:\esp32\cable_tester_rs485`。`D:\esp32\cable_tester` 保持原有功能；本轮误写到旧工程的 GUI、新增控制器和测试已撤回。

## 要求与实现

1. 控制台提供左右 Master、从机数量、节点（`slave1-G1`～`slave10-G24`）和闭合后等待时间。四线测量路径、双节点四线闭合及底层指令保留在“调试”页。
2. 全矩阵复位覆盖当前在线的全部 Master、每条 RS485 总线的全部从机以及直接连接 Wi-Fi 的 Slave，与控制台当前选择的主机、目标及模式无关。

## 单点测量

按当前硬件连接，左端选择 master1，右端选择 master2。填写各侧连续接入的从机数量，选择两端节点并输入 0～5 秒等待时间，支持 0.001 秒步长。

执行顺序为：检查主机角色及从机在线情况 → 建立右端单点计划 → 发送 `TOPO_POINT` → 固件闭合右端节点、闭合左端节点 → 固件等待设定时间 → XD31H 读取 → 两端复位 → GUI 显示结果。

等待参数由固件执行，不通过上位机的网络往返或 Tk 定时器计时；实际等待精度受固件 RTOS tick 影响。此功能用于单次调试，读数未经校准。它使用既有 `TOPO_POINT` 协议，超时或断线会结束并尝试复位，不自动重测或续传，拓扑扫描的 Flash 续传流程保持原样。尚未确认的扫描缓存会阻止单点调试，不会被删除。

## 全矩阵复位

对每台在线 Master 发送本机 `RESET`、`BUS broadcast RESET`，再依次向该总线 `slave1`～`slave10` 单播 `RESET`；对每台 Wi-Fi 直连 Slave 发送 `RESET`。

只有收到目标的 `OK RESET` 才算逐台确认。`OK FORWARDED` 只表示转发，`OK BUS_SENT broadcast RESET` 只表示广播已发送。所有未响应地址保留为“未确认”，可能是未接入的从机；需结合现场接入清单判断。某个目标失败后仍尝试其余目标。

复位沿用现有固件语义：master1 的四条固定 Kelvin 仪表通路保留，master2 和从机恢复全断。固件有活动拓扑会话时可能拒绝普通复位，GUI 会保留其错误回包，不会清除缓存来强行解锁。
