# 手动 G1-G1 零阻值诊断与修复

## 实测结论

2026-09-07，通过正在运行的上位机本机 TCP 路由（127.0.0.1:3333）操作真实设备。
独立 `NODE DIAG-*` 客户端逐条发送命令，收到设备 `RESULT` 后才继续，原始收发帧保存在
`reports/manual_diagnostics/`。没有重启上位机、烧录设备、更改校准或重新扫描整根线缆。

| 对照条件 | master1 原始电阻 | raw / range |
|---|---:|---|
| 原拓扑报告 `topology_20260907_211907_d7ba9731.json`，G1-G1 | 25.340 Ω | 2534 / 1 |
| 主机保留残余闭合，右侧改为偶数 X 电流、奇数 X 电压 | 0.000 Ω | 0 / 2 |
| 仅执行 master1 本地 RESET，保留相同从机选路 | 25.340 Ω | 2534 / 1 |
| 上述通路再读取一次 | 25.330 Ω | 2533 / 1 |
| 清理后的 master1，两侧从机恢复用户原手动选路 | 25.330 Ω | 2533 / 1 |

该对照支持：本次零值由 master1 本地残余闭合形成的旁路引起。
右侧触点顺序与拓扑不同，但恢复该顺序后读数仍正常，不能把顺序差异当作本次根因。
这不是 GUI 校准或格式化把 25 Ω 改成 0 Ω；设备返回的原始值已经是零。
部分网络回包延迟约 5~11 秒，单独记录为通信现象，不作为本次零值的解释。

## 故障选路

master1 回读的 S1 位图为 `0500000A0000060000090000000000`：

- 固定仪表通路：X0-Y0、X1-Y1、X2-Y2、X3-Y3。
- 额外闭合：X1-Y2、X3-Y1、X2-Y0、X0-Y3。

额外四点与“正端 X0/X1、负端 X2/X3”的双节点闭合命令一致。
在 master1 本地使用这组命令，会让固定仪表 X 同时接到两个 Y 总线：
例如 X1-Y1 加 X1-Y2 直接连通 V- 与 V+；X0-Y0 加 X0-Y3 连通 I- 与 I+。
现有日志不足以重建用户之前的全部操作顺序，但实际旁路状态和清理前后电阻均已记录。

旧固件只禁止断开固定的 Xn-Yn，仍允许这些 X 改接到其他 Y。
手动 `SWITCH` 是增量操作，`MEASURE` 直接读取仪表，不清理其他矩阵。
拓扑流程的 `clear_local()` 会先清理主机额外选路，所以两种工作流会出现不同结果。

## 修改

- 上位机 `RouterState` 的 GUI 与网络客户端发送入口均检查 master1 本地固定仪表端。
  固定 X0~X3 不允许断开对应 Y，也不允许再闭合到其他 Y。
  从机 `BUS` 选路、master2、其他主机 X，以及用于清理残余的 OFF/RESET 保持可用。
- 主机驱动 `ch446_set_crosspoint()` 增加同样的保护，包含 Y4。
  `ch446_connect_kelvin_pair()` 在 RESET 或任何闭合之前检查两端，拒绝占用固定仪表 X。
- 新增上位机路由回归用例，以及实际 C 驱动的交叉闭合拒绝、CONNECT 无副作用拒绝、旧残余清理用例。
- `scripts/manual_probe.py` 保留为命令行诊断工具；只允许本地/第一台从机的明确诊断命令。
  运行前必须确认自动测试空闲，它不持有 GUI 工作流锁；失败不自动重发，结束不自动复位。

## 验证与生效

- 修复前新增回归测试确实复现上位机转发错误选路、固件接受旁路的行为。
- 修复后完整 unittest：280 项通过，无跳过。
- ESP-IDF 5.5.4 / ESP32-S3 主机编译通过；镜像 `master/build/esp32s3_cable_tester_master.bin`，
  配置身份 master1，应用分区剩余约 21%。
- 实物验证的是旧固件清理旁路后的恢复；新增保护已做主机测试和目标编译，尚未烧录实机验证。
- 上位机保护需要重新启动修改后的程序生效；当前运行中的 GUI 保持未重启。

最终保留：master1 本地仅四条固定仪表通路，master2 本地全断；左侧 slave1 的 G1 为
S1 X0-Y0 / X1-Y1，右侧 slave1 的 G1 为 S1 X0-Y2 / X1-Y3（用户原手动选路）。
从机其他点全断。最后一次实测为 25.330 Ω。STATUS 是软件影子状态，不是硬件触点独立回读。
