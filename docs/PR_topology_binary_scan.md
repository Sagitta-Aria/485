# 拓扑编码与二分扫描

日期：2026-09-07。工程：`D:\esp32\cable_tester_rs485`。

## 问题与行为

一对多接线可能使原有编码初筛产生异常签名；若某个分组误判为断开，编码候选还可能遗漏真实分支。扫描窗口现提供“拓扑编码”“二分扫描”两种选择，默认保留拓扑编码。二分方式不要求预先知道接了几根，也不限制分支所在的从机。

| 方法 | 搜索与确认 | 次数与兼容性 |
|---|---|---|
| 拓扑编码 | 恒重编码初筛、异常逐点补测、接线单点电阻 | 保留原有次数计算和旧固件兼容协议 |
| 二分扫描 | 两半递归搜索、可选 1～10 次采样、剩余区间复查、矛盾区间逐点补测 | 次数随实际接线变化，默认每项采样 1 次；两块 Master 都需支持新版区间测量和可靠缓存 |

选择在扫描期间锁定。二分结果显示全部已确认目标及其单点电阻，进度显示“二分确认”。预期接线设置仅用于结果比较，不用于提前排除目标或指定分支数量。原有 `SHORT` 状态在界面显示“多端导通”，它描述同一源端可达多个目标；是否符合线束设计仍需结合实际预期。

## 二分规则与准确性边界

1. 对一个左端口测量整个右端范围。“二分采样次数”可设置 1～10 次，默认 1 次，控制每次区间或单点判定的独立采样数。单次使用原始分类及错误原因；选择多次时，只有各次分类均一致且确定才得到导通或断开结论，否则保留未确定，不采用多数投票。
2. 导通或未确定的区间继续拆分，两半都搜索。只有单独选择某个目标并确认导通后，才加入已确认接线；找到一个或四个分支都不会提前结束搜索。
3. 初次搜索后排除已确认目标，再测量其余连续区间。剩余区间导通或未确定时，对该区间逐点复核；父区间导通而子区间均无导通时也逐点复核。
4. 未完成或仍有未知单点时保留 `UNKNOWN`。检测到分组矛盾、重复分类不一致等证据时保留冲突；即使补测找回分支，完成的行仍标为 `INCONSISTENT`，不静默改成正常。

该搜索在稳定的低阻 OR 模型下不依赖分支数量。分组测量仍由 XD31H 完成，真实并联通路、接触和稳定时间可能使分组判定与逐点判定不一致。重复确认和剩余区间复查不能排除持续、重复的错误断开读数，因此不能承诺任何测量条件下都绝不漏支。实机需要验证分组判定、单点判定、阈值及稳定时间。

软件给出端口之间的可达关系，不推断内部接头位置，也不能发现与另一端隔离的所有同侧短接。单点电阻仍是未校准的端到端读数，短接网络中可能是等效电阻。

## 任务与可靠传输

二分决策由上位机执行，Master 负责每次区间或单点的选路、等待、仪表读取和持久缓存。接收端沿用 `TOPO_BEGIN2`、`TOPO_MASK`、`TOPO_SEAL` 建立可靠会话，二分采样不使用编码结果。

新增命令及载荷：

```text
TOPO_RANGE2 <session> <job> <peer> <left_modules> <source> <first> <end> <settle_ms>
TOPO_SPAN2 <session> <first> <end> <token>
OK TOPO_SPAN2 <token>
TOPO_RANGE_SAMPLE <session> <source> <first> <end> <measurement_payload>
```

端口坐标从 0 开始，区间为 `[first, end)`，允许跨从机；例如 `[23, 25)` 对应 `slave1-G24` 与 `slave2-G1`。接收端校验区间不超过当前计划的实际端口数，同时为区间之外的模块下发零掩码。单端口仍用 `TOPO_POINT2`。

每次采样都有独立任务号，选择一次时只启动一个采样任务，不再隐含执行三次。相同任务号的重试必须保持任务类型、源端口、目标区间、模块数及稳定时间完全一致。接收端准备成功后回显选择令牌，测量完成、写入 Flash 前再通过 `TOPO_VALIDATE` 核对；中途掉线导致选路失效时只重测尚未提交的读数。

采样次数控制每次判定，剩余区间复查和矛盾补测仍可能再次访问相同区间或端口，因此不是该端口在整轮扫描中的采样总上限。在判定结果相同、无中断时，从三次改为一次将采样任务和样本数量降至原来的三分之一，固定的发现和计划下发等开销不随之减少。当前多层矛盾补测尚未去重，不应用调整次数后的正常耗时推断所有异常场景的耗时上限。

原始样本和任务终止记录均经 Flash、`TOPO_FETCH`、上位机 SQLite 持久提交、`TOPO_ACK`。设备只回收已确认的完整数据扇区，缓存达到 70% 暂停、低于 50% 且控制连接恢复后继续。详情见 [Flash 缓存与断线续传](PR_topology_flash_resume.md)。二分方式没有离线自治功能：Master 间控制依赖上位机路由，断网暂停，恢复后继续；MCU 重启或上位机进程重启只能先回收旧数据，物理扫描需重新开始。

## 能力与错误

`TOPO_INFO` 新增 `binary=1 cache_error=<ESP-IDF错误名>`，并继续报告 `reliable`、`cache_ready` 和缓存位置。二分扫描要求两端都支持 `binary=1 reliable=1`，否则报 `BINARY_UNSUPPORTED`；缓存不就绪时报 `CACHE_UNAVAILABLE` 并附上固件错误名。旧固件未提供具体错误时显示 `UNKNOWN`。

错误名用于区分分区缺失、日志或 Flash 访问错误，不会自动清除缓存，也不表示先前设备上的缓存故障已经修复。缺少拓扑分区的设备须升级分区表；其他错误应依据具体返回码和已有缓存判断，不能将整片擦除作为常规恢复操作。

## 报告与代码

JSON 保持 `schema: 2`，新增 `scan_method`。二分模式新增：

- `binary_confirmation_repeats` 保存所选的 1～10 次；`binary_samples` 保存每次读数的 `source`、`first`、`end`、`attempt`、`job_id`、`kind` 及原始仪表字段。SQLite 会话配置也记录采样次数。
- 每行 `binary_complete` 和 `binary_conflicts`，记录完成状态和矛盾区间。
- `rounds=0`、`weight=0`，`codebook`、`code_samples` 为空，签名为空。
- `point_samples` 保存单点判定结果。单次直接使用原始样本；多次分类不一致为 `UNSTABLE_READING`，分类一致时按阻值排序取中间位置的真实样本及原始响应，偶数次取中间两个中的后一个，不生成平均阻值。全部原始读数保留。

CSV 在原有列之后追加 `scan_method`、`binary_samples_raw`、`binary_confirmation_repeats`。未完成或不一致的行只将已有确定单点写为 0/1，其余为 `?`，不将未测单元填成断路。

主要文件：

- `topology_binary.py`：独立二分搜索、剩余区间复查和冲突记录。
- `topology_scan.py`：方法选择、可配置采样次数、可靠任务、报告和错误信息。
- `topology_panel.py`：方法单选控件、状态和结果详情。
- `master/main/topology_scan.c`：区间任务、区间掩码、令牌验证及能力响应。

## 升级与实机验收

采样次数选项仅修改上位机调度，已有支持二分扫描的固件无需为此再次升级。重启上位机后默认采样一次，在二分模式旁可修改为 1～10 次，扫描期间锁定；编码模式禁用该控件，原有编码采样规则不受该设置影响。下列固件升级步骤适用于尚未部署二分功能的设备。

1. 两块 Master 均需升级支持区间命令的固件。尚未部署可靠缓存分区的设备还必须升级分区表，不能只烧录应用 bin；已使用相同拓扑分区的设备无需为二分方式改动分区布局。
2. 当前构建身份为 `master1`。`master2` 需按现有身份配置单独构建，不得把 master1 镜像直接烧入两台设备。从机无需为本次改动升级。
3. 重启 `_rs485` 上位机，选择二分扫描。先用已知一对四接线核对实际端口及电阻，再覆盖分支跨模块、单支、开路和更多分支。
4. 对相同接线改变稳定时间、重复扫描，并比较分组与单点原始读数；有冲突时保留报告。测试两端分别掉线重连后，结果坐标和电阻仍一致。

本次只修改和验证软件，没有烧录、访问串口、启动实物扫描或重启正在运行的上位机。GPIO、WiFi 身份和凭据、校准及历史报告未因本次改动而调整。
